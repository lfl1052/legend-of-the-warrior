# Forest Chapter Redesign — Godot 4.7

## Game Thesis

- **玩家幻想**：以敏捷剑士身份穿越受污染的森林，通过观察敌人意图、利用高低差和短窗口连击夺回道路。
- **视角**：横版跟随相机；关卡边界由显式 `camera_bounds` 定义，不由装饰图块反推。
- **主要动作**：移动、跳跃、蹬墙跳、滑铲、三段攻击、交互。
- **单次目标时长**：`level_demo` 3～5 分钟，`level_2` 首次通关 8～12 分钟。

## Gameplay Blueprint

### 核心循环

1. 读取敌人轮廓、朝向、攻击范围和地形高差。
2. 选择接近、越过、滑铲或攻击。
3. 在启动—生效—恢复窗口中完成命中或撤离。
4. 通过检查点、可破坏物和奖励恢复节奏。
5. 将获得的代币用于技能或路线解锁。

### 玩家手感目标

- 地面移动有短加速和减速，不在一帧内从静止跳到最高速。
- 郊狼时间和跳跃缓冲各约 `0.12s`。
- 蹬墙跳后约 `0.10s` 锁定离墙水平速度，避免立即被反向输入抵消。
- 普通攻击要求近身承诺；滑铲负责穿越危险区，不替代攻击。
- 相机必须在敌人首次能威胁玩家前显示其轮廓。

### 失败与奖励

- 检查点放在“组合”和“Boss 测试”之前，失败后不重复整段教学。
- 普通敌人用于练习，不通过纯血量堆叠增加难度。
- 宝箱和地图代币位于完成战斗后的安全区，形成明确收束。

## Level Blueprint

### `level_demo`：操作确认区

- **目标**：确认移动、跳跃、攻击、存档和交互。
- **结构**：安全出生区 → 单只地面敌人 → 单只空中敌人 → 奖励 → 通往森林。
- **完成条件**：到达右侧出口进入 `level_2`。

### `level_2`：森林敌人组合课

关卡从左向右推进，目标宽度约 5,120 像素。

| 区段 | 大致 X 范围 | 教学作用 | 敌人/内容 |
| --- | ---: | --- | --- |
| Arrival | -2400～-1900 | 安全定向与检查点 | 出生点、返回入口、低平台 |
| Introduce | -1900～-1200 | 熟悉平台节奏 | 无敌人低压移动区 |
| Confirm | -1200～-500 | 确认攻击恢复与缩壳反应 | Snail、可破坏物 |
| Combine | -500～300 | 处理空中突袭 | Bee、高低双路线 |
| Recover | 300～650 | 降压与保存 | 检查点、收集物 |
| Stress | 650～1450 | 连续平台移动测试 | 较高平台、路线切换 |
| Test | 1450～2100 | 独立 Boss 读招测试 | Boss Enemy |
| Payoff | 2100～2400 | 奖励与离场 | 宝箱、地图代币、出口 |

### 地形规则

- 连续主体地面使用 `GeometryTiles: TileMapLayer`，碰撞来自 `TileSet`，不再叠加大矩形地板。
- 草冠是 Geometry 扩展顶面的一部分；小型植物使用 `ForegroundTiles: TileMapLayer`，不得承担玩法碰撞。
- 背景树和远景使用 `BackgroundTiles` 或独立装饰节点，不进入相机/玩法边界计算。
- 高台按“顶面行 + 宽度 + 填充深度”配置；平台边缘必须完整封边。
- 森林图集通过派生的左右 1×2 草岩凹角支持贴地主高台；洞穴下侧凹角和 45° 泥土斜坡仍需补充素材。
- 所有 Geometry Terrain 图块提供 World 碰撞，Background 与 Foreground 装饰层保持无碰撞。
- 暂不加入无底坑，先保证高速移动和敌人追击的碰撞公平性。

## UI Blueprint

- 常驻 HUD 只保留生命与能量。
- 交互提示只在可交互物附近显示。
- 奖励提示位于上方中央，短时出现后自动消失。
- 关卡分区和敌人教学优先通过空间与敌人组合表达，不新增文字教学面板。

## Asset And Data Blueprint

- `data/level_layouts.json` 以稳定 `layout_id` 描述地面范围、高台和装饰种子。
- `data/forest_tileset.tres` 负责图块视觉与 World 层碰撞。
- 游戏逻辑引用 `layout_id`，不把图块坐标散落在关卡场景脚本中。
- 角色和敌人场景继续使用统一原点、朝向和独立身体/攻击碰撞体。

敌人职责：

| 敌人 | 战斗角色 | 玩家主要判断 |
| --- | --- | --- |
| Snail | 防御型阻挡者 | 受击缩壳后停止贪刀 |
| Bee | 空中突袭者 | 观察启动、攻击窗口和撤退 |
| Boss Enemy | 综合测试 | 读蓄力—生效—恢复三段技能 |

## Implementation Handoff

- **模拟层**：玩家状态、敌人状态、伤害、奖励和存档继续由脚本/数据负责。
- **渲染层**：场景、动画、`TileMapLayer` 和特效只表现模拟结果。
- **物理层**：身体碰撞、攻击盒和 TileSet 碰撞职责分离；装饰层无碰撞。
- **相机层**：只跟随玩家并服从显式边界，不参与敌人发现或关卡完成逻辑。
- **数据层**：关卡地形配置通过稳定 ID 读取，避免每个场景复制一套绘制算法。

## Playtest Blueprint

必须验证以下代表状态：

1. 出生后 3 秒内能看懂前进方向。
2. 玩家可在平台边缘稳定跳跃，郊狼时间与缓冲可感知但不过度。
3. 每类敌人在首次造成伤害前已经进入可读视野。
4. 地面敌人不会在平台边缘坠落或卡进 TileMap 碰撞。
5. 地空组合战中敌人轮廓、攻击盒和前景装饰不互相遮挡。
6. Boss 前检查点有效，死亡重试不要求重复前半关。
7. 奖励区无主动敌人，出口可正常触发。

## Quality Gates

- `level_demo` 与 `level_2` 均只使用 `TileMapLayer` 地形碰撞，不存在重叠大地板碰撞。
- 地图至少包含 Background/Geometry/Foreground 三层职责。
- 玩家移动、跳跃缓冲、郊狼时间和墙跳锁定有自动化覆盖。
- 六类敌人的身体与攻击碰撞体通过现有资产测试。
- 关卡集成测试覆盖分区顺序、出生/检查点/出口位置和 TileMap 碰撞。
- Godot 4.7 headless import、单位测试、关卡集成测试和冒烟测试全部通过。
