## 1. 视频要点

### 1.1 动态瓦片

视频没有逐格手选地面，而是先建立 Rule Tile，再由当前单元周围的 8 邻域决定结果：

1. 从完整图集中找出顶边、底边、左右墙、外角、内角、中心和窄条等拓扑。
2. 为每种拓扑配置 3×3 邻接矩阵。
3. 同一拓扑可提供多个随机变体，减少连续地面的重复感。
4. 动画图块使用帧序列和播放速度配置；瀑布配置完成后仍按普通瓦片绘制。

关键结论是：**关卡数据只描述哪里是地形，TileSet 负责决定那里应该显示哪一块图。** 角和边不应散落在关卡脚本的坐标判断里。

配套笔记还强调：同一个位置若同时满足多条规则，Unity 会优先使用列表中靠上的规则。因此更具体的凹角、封口规则必须优先于通用边缘规则。在 Godot Terrain 中应避免让不同用途的图块共享同一组 peering bits；同一 pattern 下只放可互换的随机变体。

### 1.2 场景绘制与叠层

视频先统一素材导入，再绘制场景：

- 像素素材按固定网格切片，使用 Point/Nearest 过滤，不进行有损压缩。
- 实体平台、远景、近景和前景遮挡分别放入独立 Tilemap。
- 绘制前先选择目标层，避免装饰误画进实体层。
- 只有平台层承担碰撞；前景和背景只负责画面。
- 先画主体轮廓，再补背景和前景，最后检查遮挡关系和接缝。

## 2. Unity 与 Godot 4.7 对照

| 视频概念 | Godot 4.7 对应 | 本项目约定 |
| --- | --- | --- |
| Sprite Multiple / 16 PPU | 16×16 atlas grid、Nearest 过滤 | 地图图块保持 16×16 逻辑网格 |
| Rule Tile | `TileSet Terrain Set` | `Terrain Set 0 / Forest Ground` |
| 3×3 邻接矩阵 | Terrain peering bits | 主体使用角匹配规则 |
| 随机输出 | 同一 Terrain pattern 的多个 atlas tile / probability | 中间草边和泥土提供多个等概率变体 |
| Animated Tile | `TileSetAtlasSource` animation | 水面、瀑布放入独立 `WaterTiles` |
| 多个 Tilemap | 多个 `TileMapLayer` | Background / Geometry / Foreground |
| Sorting Layer / Order | `z_index`、Y Sort | 见下一节 |

运行时只向实体层提交占用单元：

```gdscript
geometry.set_cells_terrain_connect(cells, 0, 0, true)
```

`set_cells_terrain_connect()` 会根据相邻占用单元选择边、角和中心；最后一个参数启用空地边界连接，使平台外轮廓能正确封边。

## 3. 图层职责与顺序

本项目森林关卡使用以下顺序：

```text
Canvas background                 z = -10
Parallax far / middle / near      z = -9 / -8 / -7
BackgroundTiles                   z = -2  无碰撞
GeometryTiles                     z = -1  有 World 碰撞
Actors                            z =  0  或 Y Sort
WaterTiles                        z =  0  无碰撞（视觉动画）
ForegroundTiles                   z =  2  无碰撞
FX / HUD                          z > 2 / CanvasLayer
```

- `BackgroundTiles`：地面后方的小叶丛、远处藤蔓或不会遮挡角色的装饰。
- `GeometryTiles`：唯一的连续实体地形来源；图块视觉和碰撞必须使用同一逻辑单元。
- `ForegroundTiles`：草、花、前景枝叶等稀疏遮挡，不得带 World 碰撞。
- 水面使用独立 `WaterTiles`，不要混进 Geometry。当前资源直接在 `Forest-1.png` 上配置
  4 帧水面和 3 帧水体 atlas 动画；瀑布以后沿用同一层与动画规则。
- 视差树必须位于 Geometry 后方；树根可延伸到地面以下，但必须被实体泥土遮住，不能穿透显示在地板内部。

## 4. Forest-1 图集审计

`Forest-1.png` 为 528×336，即 33×21 个 16px 单元。当前关卡使用的主土壤组位于 atlas `(0,0)` 到 `(4,4)`：

- `(0..4, 0..1)`：草冠与泥土顶面，组合为 1×2 扩展图块。
- `(0, 2..3)` / `(4, 2..3)`：左右侧墙。
- `(1..3, 2..3)`：内部泥土变体。
- `(0..4, 4)`：底边和底部外角。
- 原图 `(5,4)` / `(6,4)`：右侧、左侧草岩凹角的下半格；`(5,3)/(6,3)` 是独立岩石，不能纵向合并。
- 原图 `(7,3)`：凹角上半格草冠来源。项目将它按左右岩壁轮廓裁切，并与 `(6,4)/(5,4)` 合成为 `forest_ground_inner_corners.png` 的两个 1×2 图块。完整高度与普通草坪一致，同时不会把整格草画进土墙。
- `(10,17)`、`(15,17)`、`(10,18)`、`(15,18)`：各自包含完整的单格蘑菇，可安全用于表面散布。
- 旧实现使用的 `(6..8,17)` 是复合叶片的碎块，`(3,18)` 和 `(5,18)` 则分别截到了白色道具和钥匙，不能作为自然装饰。
- atlas 右半部分的大树冠、灌木和水体是独立素材组，不能当作主土壤的内角混用。

这组土壤可表达矩形岛，并通过 `(5,4)/(6,4)` 表达贴地高台需要的两个上侧凹内角。它仍未提供洞穴顶面所需的下侧凹角、完整单格岛、单格宽竖条、单格高横条和 45° 泥土斜坡。因此：

1. Terrain Set 自动选择矩形岛、贴地高台的边、角和中心，替代关卡脚本硬编码选图。
2. `merge_with_ground = true` 的平台必须与主地面相接，生成左右凹角；普通悬空平台仍需保留空气间隔。
3. 平台宽度至少为 2，视觉总高度至少为 2 格（布局的 `depth >= 1`，另加 1 格顶面）。洞穴、单格窄柱等拓扑仍要等相应图块补齐。
4. 不得用树冠、另一种棕色土壤或透明填充伪装缺失的内角。

## 5. 项目绘制流程

### 5.1 准备 TileSet

1. 注册实际使用的 atlas 区域，不把整张图集所有透明单元都导入。
2. 将草冠和泥土顶面合成 1×2 tile，并设置 `texture_origin.y = 8`。
3. 建立 `Forest Ground` Terrain，配置矩形岛所需 9 类角模式。
4. 将同类顶边和中心作为同一 pattern 的变体。
5. 只给主地形图块添加 World 物理层；装饰图块不添加碰撞。

### 5.2 生成关卡

1. 从 `data/level_layouts.json` 读取稳定 `layout_id`。
2. 将主地面和各个平台转换成占用单元集合。
3. 验证地块不会相交、不会产生未支持的凹角，并且宽度、深度至少为 2。
4. 一次性调用 `set_cells_terrain_connect()` 绘制 Geometry。
5. 使用稳定 seed 在 Background / Foreground 做稀疏装饰；装饰不改变碰撞和通关路线。

### 5.3 视觉检查

- 以 640×360 逻辑视口检查，放大时保持整数缩放和 Nearest。
- 检查每个平台四个外角、长边变体和底边是否连续。
- 检查视差树在泥土区域内是否完全被 Geometry 遮挡。
- 检查角色脚底基线与草顶一致，碰撞不得高于可见草面或低到角色明显下沉。
- 检查 Background / Foreground 的 `collision_enabled == false`。

### 5.4 草冠与角色遮挡

atlas `(0..4,0)` 不是独立碰撞草坪，而是与 `(0..4,1)` 合成的 1×2 扩展顶面。逻辑碰撞仍位于地面单元；上方草尖只参与显示。`GeometryTiles.z_index = -1`、角色和敌人默认 `z_index = 0`，所以草边可以贴近脚底，但不能遮住角色身体、攻击特效或敌人轮廓。不得把这排草冠复制到 `ForegroundTiles`，否则会产生双草边和脚部遮挡。

左右凹角也必须遵守同一 1×2 高度契约。直接使用单格 `(5,4)/(6,4)` 会缺少草冠；整格覆盖 `(7,3)` 又会让草深入竖墙。当前派生图按底部草岩像素的绿色轮廓裁切上半格，只在低地一侧保留草冠，靠墙一侧透明。

### 5.5 斜坡现状

当前关卡只有水平草面、竖墙和凹角高台，**没有真正的物理斜坡**。`Forest-1.png` 的 `(5..8,0..2)` 是大型叶丛/树冠轮廓，不是带泥土截面的 45° 可行走斜坡，直接加斜坡碰撞会造成“视觉踩空”。后续若增加斜坡，应新增同调色板的左右坡面图块，并为每个坡向配置三角形碰撞；在素材补齐前使用分层高台，不用不可见斜坡或叶丛冒充地面。

## 6. 动画瓦片规范

视频中的瀑布方法可直接映射到 Godot atlas 动画：连续帧必须尺寸一致、锚点一致，并由一个 atlas tile 管理帧数和速度。水体层单独设置 z 和碰撞；只有玩法明确要求时才给水体增加 Area2D 或专用物理逻辑，不用装饰动画承担地面碰撞。

当前 `forest_water_tileset.tres` 已实现：

- `(6,14)` 起始的 4 帧水面，3 FPS；
- `(3,13)`、`(3,14)`、`(3,15)` 起始的三组 3 帧水体，2 FPS；
- 全部直接引用 `Forest-1.png`，不生成独立水体帧 PNG。

## 7. 验收标准

- 关卡脚本不再按 `left/right/y_offset` 硬编码 atlas 坐标。
- `forest_tileset.tres` 包含可查询的 Terrain Set 和 Terrain 名称。
- Geometry 使用 terrain connect 生成，背景和前景保持无碰撞。
- 同类顶边和内部泥土能出现稳定、可复现的视觉变体。
- Demo 与 Level 2 可加载、可通关，无 TileMap 错误和 ObjectDB leak。
- 三张代表性截图分别覆盖：主地面、悬空平台四角、前中后景遮挡。
